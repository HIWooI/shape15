## 1. 웹 패널 멈춤 해결

프레임 간격 최대 **4017 ms → 308 ms** (p99 295 → 100), 실효 8.6 → 16.1 FPS.
논블로킹 IK 교환(`IKLink`)이 원인이 맞았다. 기존 `replay_delay.py`로는 검증이
불가능했음을 발견하고(자체 블로킹 교환 + 워커 렌더 부재) `--ik_async`와 `--ik_render`를
추가해 재현·측정했다.

## 2. 웹 캘리브레이션 버튼

**Calibrate** → `GET /calibrate` → T-포즈 프롬프트 → 워커가 15프레임으로 뼈 스케일과
floor 재측정. 요청은 첫 confidence의 **부호 비트**로 전달해 고정 크기 프로토콜을 유지.

실측으로 거른 함정 셋 (공통 교훈: 캘리브레이션이 솔버를 흔들면 안 된다):
- 재측정 중 floor를 0으로 두면 로봇이 0.7 m 떠오르고 회복 불가
- 이전 스케일 유지는 체형이 다른 사람을 사거리 밖으로 밀어 더 나쁨
- 웜스타트 리셋은 **재**캘리브레이션에서만 이득

결과: 1.4배 체형 교체 후 K1 **0.1 mm** 복귀. G1은 158 mm(기록된 결함).

## 3. K1 교사 결함 발견 — 이 세션의 최대 사건

`outputs/dataset_soma_vs_k1.mp4`(사람 vs 교사)를 보고 사용자가 왼다리가 안 맞는다고
지적. **수치 검사(라벨 자기일관성 0.18°)로 "교사 정상"이라 판단했던 것이 틀렸다 —
자기일관성은 정확성이 아니다.**

원인: `soma-retargeter` 서브모듈이 PR#1에 고정돼 있었고, 그 시점 `ai_sapiens` 설정은
`_provenance`에 스스로 "G1 IK objective policy and G1-style target frames"를 쓴 **실험
후보**라 적혀 있었으며 `feet_stabilizer_config`가 G1 것을 가리켰다. 업스트림 PR#2/#3이
K1 전용 feet stabilizer와 프록시 바디를 추가한 상태였다.

| clip 17 (2,418프레임) | 병리 프레임 |
|---|---|
| 구버전 | 50.4% |
| **업그레이드(배포 그대로)** | **1.0%** |
| 업그레이드 + post_processing 강제 ON | 44.4% (더 나쁨 — 원작자 설정이 맞았다) |

조치: 서브모듈을 PR#3 + ai_sapiens 6a2af37로 상향(MJCF 24관절·URDF 23관절 이름/순서
동일 확인), 오염 라벨·모델·오프셋 전량 삭제 후 재라벨링. 전체 데이터셋 병리율
26% → **6.6%**, 테스트셋 0.5%. 무릎 한계접촉 좌/우 45.5/41.3% → 19.4/19.9%로 대칭 회복.
교사 속도도 1.2 → ~10 fps.

`outputs/k1_teacher_fix.mp4`(사람 / 구버전 / 업그레이드 3분할)로 확인 가능.

## 4. Distillation — MLP가 IK를 크게 이김

파이프라인: `make_labels.py`(다중 클립, 정렬 assert, 클립당 서브프로세스로 OOM 회피,
재시작 가능) + `make_synth.py` + `distill.py`(클립 단위 홀드아웃) + `make_offsets.py`.

**핵심 발견: 학생은 용량이 아니라 정보가 부족했다.** 14점 입력은 15.4°에서 정체하고
width·시간 컨텍스트·데이터 증가가 전부 무효였는데, 교사가 실제로 소비하는
`body_pose`(SOMA 76관절 회전, 라이브에서 공짜)를 주면 한 번에 9.5°(G1).

K1 개선 사다리:

| | K1 |
|---|---|
| PyRoki IK | 26.75° |
| MLP plain 2층 | 14.94° |
| + residual 4블록 | 13.97° |
| **+ interp 합성 (blend 0.6)** | **10.71°** |

## 5. 합성 데이터 — 샘플링 방식이 전부

기존 `box` 방식(관절 범위 1.5배 균일 샘플링)은 K1에서 **무효**였다. 원인은 양이 아니라
라벨 품질 — 분포 밖 자세를 넣으면 교사가 다리를 관절 한계로 밀어 병리가 41.3% 재발한다.

`--mode interp` 신설: 키프레임을 **실제 자세 두 개의 블렌드**로 만든다. 새 조합이지만
매니폴드를 벗어나지 않는다(병리 0.0%).

| 합성 | 병리 | 학생 오차 |
|---|---|---|
| 없음 | — | 14.26 ± 0.12° |
| box m1.5, 24클립 | 41.3% | 14.46° |
| interp blend 0.35, 8클립 | 0.0% | 11.74 ± 0.07° |
| **interp blend 0.6, 8클립** | **0.0%** | **10.79 ± 0.07°** |
| interp blend 1.0, 8클립 | 0.0% | 11.57 ± 0.05° |
| interp blend 0.35, 24클립 | 0.0% | 12.18 ± 0.26° |

**반직관적 결과 둘.** 양을 늘리면 나빠진다(8클립=실데이터와 1:1이 24클립=3:1을 이긴다).
blend는 중간값이 최적(0.35는 새 정보가 적고, 1.0은 평균으로 쏠린다).

## 6. 남은 오차의 정체

배포 모델(10.71°)의 오차 분포:

| 부위 | 오차 | 상대(교사 std 대비) |
|---|---|---|
| **팔** (10관절) | **15.74°** | 0.298 |
| 다리 (12관절) | 7.35° | 0.237 |
| 몸통 (waist_yaw) | 0.79° | 0.107 |

최악 관절은 `shoulder_yaw`(19.7~21.2°, 상대 0.44~0.46)와 `wrist_roll`(상대 0.50) —
**위치로 결정되지 않는 twist DOF**다. 잘 맞는 곳은 waist_yaw 0.79°, ankle_roll 1.4~1.6°.

자세별로는 세 조건에서 급격히 나빠진다:

| 조건 | 오차 |
|---|---|
| 손이 어깨 아래 | 5.3° |
| **손이 어깨 위** | **21.4°** |
| 양발 간격 0.06~0.24 m | 5.1° |
| **양발 간격 0.67 m 이상** | **20.6°** |
| **팔 완전히 폄** | **19.7°** |

키포인트 신뢰도는 원인이 **아니다**(최악 5%의 신뢰도 0.86 = 전체 평균 0.87). 인지 실패가
아니라 자세 자체가 어렵다.

**극단 자세 오버샘플링은 실패했다** — 상위 10%에 가중치 76%를 주니 분포가 쏠려
15.50°(균일 10.79°)로 악화됐고, 정작 어려운 자세에서도 27.94 vs 20.72로 더 나빴다.

## 7. 구조 실험 — 측정으로 정리된 것

- **residual + LayerNorm**: plain 대비 −1.3°. 4블록이 최적, 6·8블록은 악화.
  plain으로 깊게(6층 16.03°)·넓게(w4096 16.19°)는 전부 악화. `--arch res`로 편입.
- **부위별 전문가(다리/팔/몸통) + 융합층**: 정확도 동등(11.68 vs 11.74, 시드 편차 안).
  단 **파라미터 32% 절감**(5.9M vs 8.7M)이라 엣지 배포용 카드.
- **kp2d 학생**: denoiser+FK를 잘라 ~30 Hz. G1에서 15.56°(MLP 11.48° 대비 −4.1°).
  속도가 실제로 필요할 때만.

## 9. 표시: 로컬 GUI를 기본으로

브라우저 스트리밍에서 반복적으로 문제가 생겨 **로컬 창을 기본 권장으로 바꿨다.**
`--stream`을 빼면 OpenCV 창(카메라+스켈레톤)과 MuJoCo 뷰어(로봇) 두 개가 뜬다.
`DISPLAY=:1`이 필요하다(`:0`은 이 머신에 없다).

웹 페이지에만 있던 Calibrate를 키보드로도 옮겼다 — 카메라 창에서 `c`가 캘리브레이션,
`q`가 종료이고 창 하단에 안내가 뜬다.

GUI 쪽이 나은 이유: MJPEG 인코딩·전송이 없어 워커 부하가 줄고(JPEG+put 1.5 ms),
MuJoCo 뷰어를 마우스로 돌려볼 수 있으며, 브라우저 연결 문제가 없다. 스트리밍은 원격에서
봐야 할 때만 쓴다.
